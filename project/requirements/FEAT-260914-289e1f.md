# Requirements — FEAT-260914-289e1f A published calendar link joins the agenda

## Context & problem

Some of your calendar is not in iCloud. Work publishes a link — an Outlook
`reachcalendar.ics` URL — and it is not shared to the Apple account, so
`CALENDARS=… KBC Agenda` matched nothing and Harry skipped it with a log line.

A morning page that shows your children's school run and none of your meetings is worse
than no agenda at all. You would read it, see two things, and walk into a 09:00 you did not
know about.

The link was measured before this was designed. It answers 200 with 189 KB of
`text/calendar` from `Microsoft Exchange Server 2010`: **234 events, 40 with an `RRULE`,
76 carrying a `RECURRENCE-ID` override, and 2 with an `EXDATE`.** Fed through the connector's
existing expansion it produced a sensible week — 7 events on Monday, 15 on Tuesday, 2 at the
weekend. So the recurrence work already built handles Outlook, and that is not a guess.

**It also confirmed something the handmade fixtures could only assume:** a real server does
send `RECURRENCE-ID` overrides as separate `VEVENT`s inside one document, which is the case
`moved-instance.ics` was written for.

## Goals

- A published `.ics` link is read alongside the iCloud calendars, into the same agenda.
- More than one link, each with a name a person chose.
- A link that cannot be read says which one, and never quotes the link itself.
- The link is treated as a credential, because that is what it is.

## Non-goals

- **Writing to a subscribed calendar.** A published link is read-only by construction, and
  Harry does not write to calendars anyway.
- Discovering links, or subscribing on your behalf.
- `webcal://` URLs. They are `https://` with a different scheme; paste the `https` one.
- Authenticated calendar feeds that need a username. A published link carries its own
  authority in the URL.
- A second connector. See [[ADR-260914-98cc64]].

## The link is a credential

```
https://outlook.office365.com/owa/calendar/<mailbox>/<long random string>/…/reachcalendar.ics
```

**Anyone holding that URL can read that calendar.** There is no password beside it; the
random segment is the password. That decides three things:

- It lives in `.harry/connectors/icloud/.env.local`, gitignored, and declared `secret: true`.
  That declaration was not enough on its own: `context.redact()` replaced the **whole
  setting**, so a message quoting one link out of two matched nothing and went out in the
  clear. `redact` now scrubs each `Label=value` piece as well as the whole, which is what
  makes it a net rather than a best case.
- No error message, log line or alert ever contains it. They name the label instead.
- It is revoked by republishing the calendar in Outlook, which issues a new URL and kills
  the old one. That belongs in the runbook, because it is the only way to undo a leak.

## How it is configured

One setting, beside the iCloud ones, in the same shape the news connector already uses for
feeds — `Name=url`, separated by `|`:

```bash
SUBSCRIBED=KBC Agenda=https://outlook.office365.com/owa/calendar/…/reachcalendar.ics
```

The **Name** is what a person reads in a Slack line when that link breaks. The URL is split
on the first `=` so the link may contain as many more as it likes.

## Scenarios

### Scenario 1: A published link's events are in the day

```gherkin
Given SUBSCRIBED names one link serving an Outlook calendar with a 09:00 meeting today
When Harry reads today
Then that meeting is in the agenda, alongside the iCloud events
And the two are in one list, in time order, with nothing saying which calendar each came from
```

### Scenario 2: A repeating meeting from a link lands on the right day

```gherkin
Given a link serving a weekly Tuesday meeting whose series started weeks ago
When Harry reads a Tuesday
Then the meeting is at its time on that Tuesday
```

The same expansion the iCloud events already get. Outlook's document is what it was measured
against.

### Scenario 3: An overridden instance from a link is not duplicated

```gherkin
Given a link whose document carries a series and a RECURRENCE-ID override for today
When Harry reads today
Then the meeting appears once, at the overridden time
```

Measured: the real link carries 76 of these.

### Scenario 4: More than one link

```gherkin
Given SUBSCRIBED names two links
When Harry reads today
Then events from both are in the agenda
And each is fetched once
```

### Scenario 5: A link that is down fails the whole read, and says which

```gherkin
Given SUBSCRIBED names "KBC Agenda" and that link answers 404
When Harry reads today
Then the read raises rather than returning a day missing those meetings
And the message names "KBC Agenda"
And Slack carries one line naming "KBC Agenda", once per 24 hours
And neither the message nor the Slack line contains the URL
```

**A partial agenda is the failure this feature exists to prevent**, so it must not be the
failure this feature introduces. A day missing your work meetings looks exactly like a quiet
day. The whole read fails instead, the page prints "Agenda unavailable", and you go and look
at your phone — which is the right outcome.

### Scenario 6: A link answering something that is not a calendar

```gherkin
Given a link answers 200 with an HTML sign-in page, which is what an expired link does
When Harry reads today
Then the read raises, naming that link and saying it did not answer with a calendar
And Slack says the same, with the republish instruction
```

### Scenario 7: A link is fetched at most once every 5 minutes

```gherkin
Given Claude asks for three days in a row
When Harry serves them
Then each link was fetched once, not three times
And a call more than 5 minutes later fetches again
```

189 KB per call, per link. The morning page asks once; a person asking about their week asks
seven times.

### Scenario 8: No links configured changes nothing

```gherkin
Given SUBSCRIBED is empty, which is the default
When Harry reads today
Then only the iCloud calendars are read, and nothing is fetched over HTTP
```

### Scenario 9: A malformed entry in SUBSCRIBED costs one link

```gherkin
Given SUBSCRIBED is "KBC Agenda=https://…|not-a-pair"
When Harry starts
Then the malformed entry is skipped with a log line, and KBC Agenda still loads
```

### Scenario 10: The link never appears anywhere

```gherkin
Given SUBSCRIBED carries a URL with a secret segment in it
When the connector logs at DEBUG, raises on a failed fetch, and alerts
Then that URL appears in none of them
```

## When it degrades

| What broke | What the page gets | What reaches Slack |
|---|---|---|
| A link 404s, times out or is unreachable | `Agenda unavailable` — the whole agenda, deliberately | One line naming the link's label and why, once per 24 hours |
| A link answers HTML instead of a calendar | The same, saying it did not answer with a calendar | The same, with the republish instruction |
| A malformed `SUBSCRIBED` entry | The other links and all the iCloud calendars | Nothing — a typo in a setting is a log line |
| One event inside a link whose start will not parse | That event skipped by name in the log; the rest of the day renders | Nothing — see below |
| No links configured | The iCloud calendars, as before | Nothing |

**The last row is the one deliberate exception, and it needs its own argument.** A link that
cannot be *reached* tells you nothing about the day, so the read fails. One event inside it
whose start will not parse is a different thing: the other two hundred are right there, and
failing the whole morning over one malformed entry would cost the agenda every day until
somebody at work fixed their calendar. So it is skipped by name in the log — the same rule
the iCloud calendars already follow, applied here on purpose rather than by omission.

The choice in row one is the feature's whole argument, so it is worth stating plainly: **a
partial agenda is more dangerous than a missing one.** Everywhere else in Harry a dead source
costs its own section and the page renders. Here the section *is* the agenda, and a shorter
agenda is indistinguishable from a quieter day.

## Out of scope

- A second connector for subscribed links. [[ADR-260914-98cc64]].
- Saying which calendar an event came from. The page has one agenda line.
- Filtering a subscribed calendar the way `CALENDARS` filters iCloud ones. A link is one
  calendar; not naming it is how you exclude it.
- Caching a link's contents across restarts.
