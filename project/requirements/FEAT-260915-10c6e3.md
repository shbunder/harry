# Requirements — FEAT-260915-10c6e3 The connectors answer with everything the page needs

## Context & problem

The morning page has been designed and built once, as a spike, against the three connectors
that feed it. Five times the spike had to go round the back of a connector to get something
the page needs, and each of those is marked `CONTRACT:` in `scratch/digest-look.py`.

Three of the five are the difference between a page worth reading and a list:

- **The weather panel has one number.** `weather.today()` answers the day's high, low and
  rain chance. A weather panel is mostly the *shape* of the day — 19° at nine, 26° at one,
  22° at nine in the evening — and no call returns it.
- **The timetable cannot draw a block.** `icloud.today()` answers `{at, title, where}`. A
  block needs to know when the event *ends*, and a colour needs to know which *calendar* it
  came from. Without the second, every event on the page is the same grey, and the user has
  already chosen the colours: Shaun yellow, Jan green, Kids pink, KBC Agenda blue.
- **A headline has no picture.** Both feeds carry one — VRT as an Atom `enclosure`, the BBC
  as a `media:thumbnail` — and the connector throws both away while parsing.

The remaining two are smaller but have the same shape: `news.article(id)` drops the
candidate's `summary`, so a story whose page will not load has nothing to print at all; and a
candidate's `link` is the only handle on its picture.

Every one of these is a connector change, not a rendering one. The page cannot be built for
keeps until they are made, and the spike has already proved each of them is real by having to
work around it against the live sources.

## Goals

- `weather.forecast()` carries the shape of the day alongside the summary of it
- Every event carries when it ends and which calendar it is from
- Every candidate carries the picture its feed offered, and every article carries the
  summary its feed offered
- The tools Claude reads say so too — a field a connector returns and a tool drops is a
  field nobody can use

## Non-goals

- **De Tijd.** It needs a signed-in headed browser and a virtual display on the NUC; that is
  FEAT-260912-9c933f and it stays there
- **Rendering.** No PDF, no layout, no digest tool. That is FEAT-260912-0f2744
- **Fetching pictures.** The connector hands over the URL its feed published. Nothing here
  downloads an image — see ADR
- **Grouping stories by subject.** That is Claude's judgement, supplied to the digest tool
  when it exists, and Harry performs none of it

## Scenarios

### Scenario 1: the weather says what the day looks like, hour by hour

```gherkin
Given Open-Meteo answers with hourly temperatures for Leuven
When weather.forecast() is called
Then it carries hours: seventeen {at, temperature} entries, 06:00 to 22:00 inclusive
And each at is "HH:MM" in the connector's configured timezone, not UTC
And today() is unchanged — summary, high, low, rain_chance and nothing else
```

### Scenario 2: an hourly forecast that did not come back costs the strip, not the panel

```gherkin
Given Open-Meteo answers 200 with a daily block and no hourly block
When weather.forecast() is called
Then available is true, the high, low and rain chance are present, and hours is []
And nothing reaches Slack, because the day itself arrived
```

### Scenario 3: an event says when it ends

```gherkin
Given a calendar holds a timed event from 10:00 to 10:30 and an all-day event
When icloud.today() is called
Then the timed event carries ends: "10:30" — the same "HH:MM" shape as at
And at itself does not change: "10:00" for a timed event, "all day" for an all-day one
And the all-day event carries ends: null, because "all day" has no end time to draw
```

### Scenario 4: an event says which calendar it came from

```gherkin
Given the account holds two calendars named Shaun and Kids, and one published link labelled KBC Agenda
When icloud.today() is called
Then every event carries calendar: the display name of the calendar it was read from
And an event from the published link carries the link's own label
```

### Scenario 5: a calendar that will not say its name still puts its events on the page

```gherkin
Given a CalDAV calendar whose display name is missing or empty
When icloud.today() is called
Then its events are present and carry calendar: "Calendar"
And the log says at INFO which CalDAV calendar had no name, once per read
```

Only a CalDAV calendar can reach this: `read_links` refuses a published link with no label,
so a link always has one. What is logged is the calendar's URL inside the iCloud account,
which needs the app password to use and is not itself a credential. **A published link's URL
is a credential and is never logged** — that rule does not change here.

### Scenario 6: a candidate carries its picture

```gherkin
Given VRT's feed publishes an Atom enclosure and the BBC's publishes a media:thumbnail
When news.search(detail='full') is called
Then every candidate carries image: the URL the feed published, or null
And a BBC thumbnail URL asks for the 800px size rather than the 240px one the feed offers
And a concise candidate carries image too: whether a story has a picture is part of choosing
    which one leads the page, and forty URLs are four kilobytes
```

### Scenario 7: a feed with no picture is not a broken feed

```gherkin
Given a feed whose items carry no image at all — tests/fixtures/news/collision.xml
When news.search(detail='full') is called
Then its candidates carry image: null
And nothing reaches Slack, because a feed without pictures is a feed, not a fault
```

### Scenario 8: an article carries what the feed said about it

```gherkin
Given a candidate whose page answers 403
When news.article(id) is called
Then it answers available: false and why, as it does today
And it also carries summary: the text the feed published, and image: the candidate's picture
And a caller has something to print
```

### Scenario 9: the tools hand the new fields on

```gherkin
Given the connectors answer with hours, ends, calendar, image and summary
When weather_forecast, icloud_list_events, news_search and news_article are called over MCP
Then each new field is present in the tool's answer
And each tool's TOOL.md says what the field is, so Claude knows it can ask
```

## When it degrades

Each addition fails on its own and costs only itself:

| What breaks | What the page still has | What reaches Slack |
|---|---|---|
| Open-Meteo answers without an hourly block | The whole weather panel except the strip | Nothing — the day arrived |
| Open-Meteo unreachable | Nothing from the weather panel; the section prints unavailable | The existing weather alert, unchanged |
| An event has no `DTEND` | The event, drawn as a point in time | Nothing — a reminder-shaped event is normal |
| A calendar will not give its name | Its events, in the uncoloured grey | Nothing; the log says which URL, once |
| A feed publishes no image | The headline, without a picture | Nothing |
| A feed's image URL is broken | The headline, without a picture — nothing here fetches it | Nothing here; whoever fetches decides |

No new alert is introduced. Every one of these is an absence in a source's own data, not a
fault in reaching it, and the existing per-fault alerts already cover the faults.

## Out of scope

- Downloading, resizing, caching or embedding any picture
- A De Tijd connector, a headed browser, or `xvfb-run`
- The digest tool, the morning-page job, and the settings that name the journal
- Any change to how candidates are ranked, deduplicated or given ids
