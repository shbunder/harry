# Requirements — FEAT-260918-5fdfa6 Every article on the page carries its own picture

## Context & problem

A story gets a picture on the morning page only if its **feed** published one. Measured on the
running stack, 2026-09-18:

| Source | Feed entries carrying a picture |
|---|---|
| VRT NWS | 46 / 46 |
| BBC News | 31 / 31 |
| **De Tijd** | **0 / 10** |
| **ROB tv** | **0 / 13** |
| **KW West-Vlaanderen** | **0 / 50** |

So three of the five sources are never illustrated, and the page has just gained two of them.
The owner noticed it as "De Tijd articles don't have a picture any more" — they never did, and
adding the local papers made the gap obvious.

**The pictures exist.** Every one of those article pages declares an `og:image`, the address a
site gives when its page is shared:

```
ROB tv   200  https://shared.robtv.be/ext/robtv/w1200/20260918-293-3687.jpg
KW       200  https://img.static-rmg.be/a/view/q75/w1600/h836/…
VRT NWS  200  https://images.vrt.be/vrtnws_share/2026/09/18/bf2dc948-…
```

**And Harry already fetches those pages.** `news.article()` downloads each one to extract its
text and then throws the HTML away. The picture is in a response it has already paid for.

De Tijd is the exception twice over: its page answers **403** to a plain request, and the
logged-in browser is the one client it serves. That is the reader the tijd connector already
is, so the picture is reachable there and nowhere else.

## Goals

- When a feed publishes no picture, use the one the article's own page declares.
- No new request. The picture comes out of a page Harry already fetched.
- De Tijd included, through the browser that already reads it.
- A story with no picture anywhere is still a story: the card prints without one.

## Non-goals

- **Downloading pictures to list candidates.** [[ADR-260915-c01ab8]] settled that a connector
  hands over a picture's address and never the picture. This changes where the address comes
  from, not that it is an address.
- Choosing a better picture than the page's own. If a site declares one, that is the one.
- Illustrating anything but news articles.
- Reading a site that blocks Harry. Nieuwsblad answers 403 and has no reader; it stays out.

## Scenarios

### Scenario 1: A feed with no picture, an article page that has one

```gherkin
Given a feed entry carrying no picture, whose article page declares an og:image
When news.article() reads it
Then the answer's "image" is that address
And no request is made beyond the one that fetched the article
```

### Scenario 2: The feed's own picture wins

```gherkin
Given a feed entry that carries a picture, whose article page declares a different og:image
When news.article() reads it
Then the answer's "image" is the feed's, unchanged
```

### Scenario 3: Neither has one

```gherkin
Given a feed entry with no picture whose article page declares no og:image
When news.article() reads it
Then "image" is null, nothing is reported, and the card prints without a picture
```

### Scenario 4: De Tijd, through the browser that can see it

```gherkin
Given a De Tijd article, whose page answers 403 to a plain request
When the tijd connector reads it through the logged-in browser
Then the og:image in the page the browser received is carried back as "image"
```

### Scenario 5: The page uses it

```gherkin
Given a pick whose feed carried no picture and whose article page declared one
When digest_build renders the page
Then the card is illustrated with that picture
```

### Scenario 6: A picture that cannot be fetched costs one picture

```gherkin
Given an article whose og:image answers 404 when the page is rendered
When digest_build renders the page
Then that card prints without a picture, the other cards keep theirs,
     and the page is delivered
```

## When it degrades

**A page declares no `og:image`.** The card prints without a picture, exactly as today.
Nothing reaches Slack — a site that publishes no picture is a site, not a fault, and this is
the existing behaviour for every feed that carries none.

**The picture's address is dead.** `digest_build` already fetches each chosen picture when it
renders; one that 404s costs that card its picture and nothing else. This feature adds more
addresses to fetch, so it makes that path more likely to be taken, not less — Scenario 6
covers it.

**De Tijd's session has lapsed.** The article is already unreadable in that case and the
connector already says so in Slack. The picture is lost with the text, and no new message is
needed for it.

**The og:image is wrong or generic.** Some sites declare a logo rather than the story's
picture. The page prints it; nobody is told. That is accepted — the alternative is Harry
judging whether a picture suits a story, which is not Harry's to do.

## Out of scope

- A picture for the weather, the agenda or the masthead.
- Caching pictures between runs.
- `twitter:image` and other fallbacks. `og:image` is what all five sources declare; a second
  spelling can be added when a source turns up that needs it.

## Open questions

- None. Every source was fetched and the addresses read before this page was written.
